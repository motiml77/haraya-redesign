# הערות מבנה האתר ואינטגרציה עם Firebase

מסמך זה מפרט את המבנה הנוכחי של האפליקציה, וכן מסביר כיצד היא בנויה כך שתוכל להתחבר בקלות ובמהירות למסד נתונים אמיתי כמו Firebase (Firestore).

## 1. מבנה האתר הנוכחי

האפליקציה בנויה באמצעות **Next.js (App Router)** ומשתמשת ב-**Tailwind CSS** לעיצוב.

### תיקיות וקבצים מרכזיים:
- **`app/page.tsx`**: העמוד הראשי של האפליקציה. מכיל את כל הלוגיקה של ממשק המשתמש (UI), כולל תצוגת הטקסט המקורי, הביאורים, מערכת התגובות (שאלות ותשובות), והסימניות.
- **`app/layout.tsx`**: מגדיר את המעטפת הכללית של האתר, כולל הגדרות שפה (`he`, `rtl`), פונטים (Frank Ruhl Libre לטקסטים ו-Assistant לממשק), ועיצוב גלובלי.
- **`app/api/content/route.ts`**: נקודת קצה (API Route) שמדמה כרגע משיכה ושמירה של נתונים (הטקסט, הביאורים והתגובות) מתוך קובץ מקומי (`data/content.json`).
- **`app/api/analytics/route.ts`**: נקודת קצה לניהול סטטיסטיקות (כמות כניסות), שומרת כרגע בקובץ מקומי (`data/analytics.json`).
- **`data/`**: תיקייה זמנית שנועדה לדמות מסד נתונים (מכילה קבצי JSON). **כאשר נעבור ל-Firebase, תיקייה זו תתייתר.**

## 2. מוכנות לחיבור ל-Firebase

האפליקציה נבנתה מראש עם "הפרדת רשויות" (Separation of Concerns) בין צד הלקוח (ה-UI) לצד השרת (ה-API). 
כדי לעבור ל-Firebase, **אין צורך לשנות כמעט שום דבר בקוד של ממשק המשתמש (`page.tsx`)**. 

כל מה שצריך לעשות הוא להחליף את הלוגיקה בתוך קבצי ה-API (`app/api/...`) כך שיפנו ל-Firebase במקום לקבצים מקומיים.

### היתרונות של המבנה הנוכחי:
1. **שליפות נתונים (Fetch):** הלקוח משתמש ב-`fetch('/api/content')`. ה-API יתחבר ל-Firebase ויחזיר את אותו מבנה JSON בדיוק.
2. **עדכון נתונים (POST):** הוספת תגובה שולחת בקשת POST ל-`/api/content`. ה-API יקבל את הבקשה ויעדכן את המסמך המתאים ב-Firestore.
3. **מבנה נתונים גמיש:** הנתונים כבר מסודרים בצורה של אובייקטים ומערכים שמתאימים באופן טבעי למבנה של NoSQL (כמו Firestore).

## 3. מבנה הנתונים הנדרש ב-Firebase (Firestore)

כאשר תקים את פרויקט ה-Firebase, מומלץ להשתמש ב-**Firestore Database**. להלן המבנה המומלץ (Collections & Documents):

### א. אוסף (Collection): `paragraphs`
אוסף זה יכיל את כל הפסקאות והטקסטים של הרב קוק.
- **שם המסמך (Document ID):** יכול להיות מזהה אוטומטי או מזהה ייחודי (למשל `orot-1-1`).
- **שדות המסמך:**
  - `book` (String): שם הספר (למשל "אורות").
  - `seder` (String): סדר/חלק (למשל "אורות מאופל").
  - `chapter` (String): פרק (למשל "ארץ ישראל").
  - `paragraphTitle` (String): כותרת הפסקה (למשל "פסקה א'").
  - `originalText` (String): הטקסט המקורי (תומך ב-Markdown וטולטיפים).
  - `tags` (Array of Strings): תגיות (למשל `["ארץ ישראל", "גאולה"]`).
  - `commentary` (Array of Objects): מערך של קטעי ביאור. כל אובייקט יכיל:
    - `id` (Number/String): מזהה ייחודי לקטע.
    - `text` (String): טקסט הביאור (תומך Markdown).
    - `sources` (Array of Objects): מקורות לביאור (אופציונלי).
  - `comments` (Array of Objects): מערך התגובות והשאלות של המשתמשים. כל אובייקט יכיל:
    - `id` (Number/String): מזהה התגובה.
    - `author` (String): שם הכותב.
    - `date` (String): תאריך.
    - `text` (String): תוכן התגובה.
    - `replies` (Array of Objects): תגובות לתגובה זו.

### ב. אוסף (Collection): `analytics`
אוסף לשמירת נתונים סטטיסטיים.
- **שם המסמך:** `general_stats`
- **שדות המסמך:**
  - `visitors` (Number): סך כל המבקרים באתר.

## 4. מדריך קצר למעבר ל-Firebase

כשתרצה לבצע את המעבר, אלו השלבים:

1. **התקנת ה-SDK:** הרץ את הפקודה `npm install firebase` ו-`firebase-admin` (לשימוש מאובטח בצד השרת).
2. **הגדרת משתני סביבה:** הוסף את מפתחות הגישה של Firebase לקובץ `.env.local`.
3. **עדכון ה-API:**
   - פתח את `app/api/content/route.ts`.
   - במקום לקרוא מקובץ ה-JSON בעזרת `fs`, השתמש ב-Firebase Admin SDK כדי לשלוף את המסמך מתוך אוסף ה-`paragraphs`.
   - במקום לכתוב לקובץ ה-JSON, השתמש ב-`db.collection('paragraphs').doc(id).update(...)` כדי להוסיף תגובות חדשות.
4. **מחיקת תיקיית `data`:** לאחר שהכל מחובר ועובד, תוכל למחוק את תיקיית `data` המקומית.

המערכת מוכנה לחלוטין למעבר זה, והוא יכול להתבצע בתוך דקות ספורות ללא פגיעה בחוויית המשתמש או בעיצוב הקיים.
